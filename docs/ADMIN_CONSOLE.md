# 实验控制台、问卷草稿与奖励核对

2026-09-23。适用：SQLite 校园采集原型。未配置公共云服务，也不执行自动支付。

## 入口

- 参与者：`http://127.0.0.1:5200/collect.html`（校园设备使用服务器局域网 IP）。
- 实验者：`http://127.0.0.1:5200/admin.html`。在服务器电脑上打开，输入 `private/collection/local-settings.json` 中的 `adminToken`。参与码不能登录控制台；管理员密钥不要发给参与者。
- `preview-immersive.html` 是内存演示入口；控制台发布的配置针对采集入口，不修改演示页面的源码默认值。

## 发布配置

1. 在流程列表上移、下移模块；调整试玩与正式任务轮数。添加或移除问卷区块，可把前测放在试玩前。已有整组问卷可先移除，再添加需要的单个问卷区块；同一题组不能重复出现。
2. 每个条件设置唯一 ID、AI 档位名称、人类平均命中率、AI 命中率、答对积分与兑换比例。率在界面中输入百分比，数据中保存 0–1。比例留空为 null，不承诺具体金额。
3. 点击“发布配置”。新会话才使用新版本；已进入的会话继续使用自己的流程和条件。多个条件使用服务端等概率独立随机分配，不保证各组人数恰好相等。
4. 配置存入 SQLite `config_revisions`，重启保留。第一次启动用环境变量/私有设置初始化；之后数据库已发布配置优先，修改环境变量不会覆盖。两页同时编辑时，后提交的旧版本会被拒绝，需重新读取后编辑。

知情同意和操作说明仍是固定入口。后台要求至少一个正式任务区块、每区块 1–500 轮、唯一模块/题组 ID、连续任务区块索引、已发布的问卷版本；试玩必须排除正式奖励。配置界面不编辑题干，题目仍在 `src/domain/questionnaire-instrument-demo.ts`。更换题库版本属于部署变更，应同时迁移/发布匹配的配置并处理旧会话，不能在采集中途直接换题。

AI 档位是程序操纵的展示/排程参数，不代表实时 LLM 测评。每区块的正确次数按轮数取整；人类平均命中率是研究者设定的参考值。此更新未改变原型的历史记录/开奖生成算法。

## 试玩与奖励

试玩共用正式机柜和操作流程，但顶部持续显示黄色“试玩环节 · 不计入正式成绩”标识。页眉、来源表现条、开奖卡都不显示试玩积分或金额。原始试次反馈仍保留 `points_awarded`，分析必须按 `scores_excluded_from_formal` 排除试玩。

完成页显示正式积分、按会话兑换比例计算的金额及稳定的 `P2-<SESSION_UUID>` 兑奖编号。编号用于人工核对，不是登录凭证，也不代表已经付款。管理汇总仅计算未排除的正式区块。实际奖励比例须由研究团队自行填写；测试脚本的 0.2 元/分仅用于隔离的合成测试数据库。

## 问卷保存与校验

- 同一浏览器标签页刷新后，恢复已输入答案、题目顺序及理解检验答错次数。草稿键包含 session_id、instrument_version、block_id；`sessionStorage` 不提供跨设备或关闭标签页后的恢复保证。
- 每次提交失败的理解题，每题增加一次 `comprehension_errors[].incorrect_count`；空白题不计为答错。它不是选择选项的点击次数。
- 本地草稿不算服务器已收到。提交后冻结答案，重试沿用同一 payload；收到保存确认后清除该页草稿。
- 新会话标记 `questionnaire_validation_version: "1.0.0"`。服务端按实际题库检查版本、区块、题目集合、重复/漏题、有效选项、必答、数值范围/步长、文本长度和理解题正确答案。旧会话保留原校验路径，避免升级后无法重放历史事件。
- `/api/events` 使用批次回执：HTTP 200 不能单独表示保存成功，必须检查 `acknowledged_event_ids`、`rejected_events` 和持久化回执。

## 核查与导出

控制台展示条件/版本、轮次与模块进度、正式积分、奖励、兑奖编号；可按会话或条件搜索，并筛选完成/未完成/待核查，导出筛选后的 JSON 或 CSV。

“理解检验曾答错”“超过 15 分钟未更新”等仅作提示，不自动剔除样本。最后更新时间取服务器保存回执，包含事件/呈现审计保存，不是参与者设备时钟；此提示不等同于认定放弃实验。

CSV 新增 `configuration_revision`、`assignment_method`、`reward_code`、`comprehension_error_count`。CSV 是试次表，会话级累计值在多行重复，不能跨行直接相加。逐题答案、错误次数、版本、题序保存在 JSON 的 `questionnaire_block_submitted` 原始事件里。

## 代码边界

- `src/admin.ts` / `src/ui/admin.html` / `admin.css`：控制台界面；密钥只放内存。
- `src/domain/admin-config.ts`：配置校验；`server/app.ts`：认证、配置版本、随机分组、进度与导出。
- `src/domain/questionnaire-validation.ts`：前后端共用题目规则；`src/ui/questionnaire-overlay.ts`：草稿与错误计数。
- `src/ui/preview-immersive.ts`：试玩标识与积分显示；`experiment-flow.ts`：完成页；`domain/reward-code.ts`：兑奖编号。

本次是 0.6.0 契约上的可选字段扩展，旧数据保持可读。后台协议仍由适配器隔离；不将管理密钥或数据库操作放进参与者代码。

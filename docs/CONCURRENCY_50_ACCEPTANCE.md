# 50 人并发验收（2026-10-10）

结论：原代码在共享网络地址下不满足 50 人集中入场；修复后，当前本地代码通过 50 个独立会话的完整流程并发测试。该结论适用于下述本机条件，不是目标服务器或现场网络的容量承诺。

## 发现与修复

原 `POST /api/session` 按连接 IP 每分钟限制 30 次，且恢复会话也占额度。原码实测 50 人同批入场：30 人成功，20 人返回 429，完整流程测试因此停止。

`server/app.ts` 现将额度调整为每个连接地址每分钟 120 次未认证入场请求，并让有效 cookie 恢复已有会话先于新入场限流处理。仍限制无效入场尝试，不信任任意 `X-Forwarded-For`。该额度为 50 人共享出口提供重试余量，不表示支持 120 人并发。若同一地址已有大量无效请求消耗额度，仍可能拒绝后续新入场。

## 实测条件与结果

- Windows 本机，AMD Ryzen 5 7500F（6 核 / 12 逻辑处理器），约 31.6 GiB 内存，Node 24.14.1。
- 测试器与构建后的 Node 服务分属两个进程，在同一电脑上；使用环回 HTTP、独立随机端口和新建临时 SQLite 数据库。没有连接真实采集库。
- 50 个独立 cookie 会话，同一个连接 IP，无错峰、无自动重试、无人工思考停顿；每人 3 轮试玩、8 轮正式任务、6 个问卷区块，交替覆盖自己判断与模拟 AI 分支。
- 每完成一个模块重新打开已认证会话；另核对事件重试和审计重试幂等性。AI 分支不调用真实模型 API，不模拟动画/逐字流式时间。

| 指标 | 结果 |
| --- | --- |
| 完成参与者 | 50 / 50 |
| 请求数（含入口 HTML、恢复与导出核验） | 5,700 |
| HTTP 错误 | 0 |
| 请求响应时间 P50 / P95 / P99 | 61.9 / 109.0 / 185.7 ms |
| 最慢请求 | 227.3 ms |
| 测试整体耗时（含启动、重启及核验） | 8.76 秒；不是人类完成实验的时间 |
| 完成轮数 | 550：150 轮试玩 + 400 轮正式任务 |
| 问卷区块 | 每人 6 个，共 300 个 |
| 重启后核验 | 50 个完成标记保留，每人的完整导出与重启前完全一致 |
| 管理员 CSV | 550 条试次记录 + 表头 |
| SQLite 完整性 | `integrity_check = ok` |

另外逐人断言：会话 ID 唯一、事件归属正确、序号连续、事件 ID 不重复、每人 11 条反馈与试次导出、重复审计仅落库一次、重复事件得到明确确认且不新增记录。客户端使用实际 HTTP adapter / ImmersiveRun / RunOrchestrator，保存失败或未确认会使测试失败。

预设性能检查为请求 P95 < 2 秒，属于本次工程检查阈值，不是研究方案参数。浏览器布局/交互另行通过现有 Playwright 采集回归检查；本测试不是同时运行 50 个真实浏览器。

## 复测命令与证据

在实验仓库执行：

```powershell
npm run build:all
$env:RUN_LOAD = '1'
npx vitest run tests/server/load-50.spec.ts
Remove-Item Env:RUN_LOAD
npm run test:run
npm run test:collection
```

负载测试默认跳过，需显式设置 `RUN_LOAD`；构建后再测，以免测试旧服务产物。模拟数据库保留在测试输出报告所列临时路径，方便复核。

- 原码失败证据：`artifacts/qa/load-50-before.json`。
- 修复后结果与逐请求耗时：`artifacts/qa/load-50-latest.json`。
- 测试服务器日志：`artifacts/qa/load-50-server.log`。
- 可重复执行的验收代码：`tests/server/load-50.spec.ts`。
- 限流保护回归：`tests/server/admission-limit.spec.ts`，第 121 次未认证请求仍返回 429，伪造转发 IP 不绕过限流。
- 本轮单元/集成回归：161 项通过；并发测试单独执行通过。类型检查、构建及相关代码 lint / 格式检查通过。
- 浏览器采集回归：8 项通过（40.8 秒），覆盖桌面/手机视口、自己/AI 分支、刷新恢复、丢失回执重试、问卷与管理控制台。

## 适用边界与运行要求

结论针对当前本地未提交版本（协议 0.6.0），不是 GitHub 上只有历史提交的版本。代码与构建产物已更新，但没有重启既有采集服务，也没有提交或推送。

既有运行进程需在没有进行中实验的窗口重新启动才会加载修复；更换服务器需重新构建并复测。现场应使用构建后的单实例采集服务；维持 SQLite 单写者部署，不能直接多副本扩容。

未覆盖：50 台真机与校园 Wi-Fi、Caddy/TLS 实际链路、公网带宽及延迟、低配云服务器、大规模既有数据库、连续多批次长期运行、真实模型 API。共享地址测试覆盖反向代理下的限流计数问题，但不等同于实际部署了 Caddy。正式轮数大幅增加后应按新配置复测。

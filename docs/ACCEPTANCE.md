# 验收标准与证据要求

本文件是后续实现的检查清单；当前尚无实验可测试。技术验证不能证明研究测量有效。

## G0：公共基础

- 类型与运行时字段检查通过；fixture 覆盖成功、拒绝、部分成功与状态不确定。
- 同一个版本的接口被 B/C/D 使用。
- demo 配置明确任务模式、来源时点、反馈、模拟建议和积分；未填写的正式参数不被自动补成事实。
- README 记录实际可用的安装、启动、构建与检查命令，不能预填未执行命令为已验证。

## G1/G2：实验与数据

| 检查 | 预期 |
|---|---|
| 实际中奖评分 | 概率最高但没中奖的预测仍算错 |
| 位置变化 | 逻辑机器 ID、显示位置和答案映射一致 |
| 独立答案锁定 | 看见建议或结果后不能回改独立预测 |
| 一致答案 | 来源选择与答案变化分开记录，不自动将相同答案当作采纳 |
| 保存语义 | 远程明确确认后才显示已上传；部分失败保留未确认事件 |
| 重复与重试 | 同 event_id 不重复计分；不同内容冲突不覆盖 |
| 断网与刷新 | 不重抽开奖、不重新分组；按声明能力恢复或明确告知不能恢复 |
| 完成判定 | 必需事件未确认时不发最终完成码 |
| 后端替换 | 相同 fixture 输出相同标准字段和评分；不修改 jsPsych 插件 |
| 信息边界 | 正式网页不能提前读取未来答案、凭证或私有种子 |
| 数据导出 | JSON 原始事件与逐题 CSV 可关联，可独立重算积分 |
| 双端界面 | 手机/电脑呈现相同证据量，触摸可操作，无关键裁切 |

优先测试正确率、状态、数据完整性和替换接口；不为了目录或文案改动创建无意义测试。

## 真后端特有检查

实际写入、重新读取、导出一致性、跨会话隔离、错误参与码、限流、凭证过期、平台重启/断线后的状态。只用 mock 通过不能勾选真实后端已验证。

JATOS 等候选平台没有的必需能力必须列出，不能用名称代替验收。前端接入真实存储但缺少服务端实验控制时，明确报告“仅存储接入完成”。

## 设备证据

模拟手机视口只证明布局初步可用；实际 iOS/Android/内置扫码浏览器需要对应设备检查。记录浏览器、视口、检查日期和结果，不把桌面缩窗称为手机实测。

## 输出

Q 在 handoffs/Q 写通过、失败、未测试三类清单，附实际命令和截图/日志位置。A 汇总后在 STATUS 标记对应里程碑。证据中不含真实参与者个人资料。

参数恢复、pilot 与研究效度另行验证，不在本清单中虚构已通过标准。

# Paper 2：前后端分层与可替换接口 v0.1

日期：2026-09-17  
状态：架构规格，尚未实现。  
用户已确认：前端采用 jsPsych；后端协议与实现应可拆分和替换。  
本文细化《老虎机原型规划》的模块边界。此前 FastAPI/PostgreSQL 的组合降为候选实现，JATOS 也不绑定为唯一后端。

## 1. 核心原则

实验规则决定界面和数据含义；托管平台只承担其声明支持的服务能力。更换后端不应改变题目定义、信息呈现、随机分组规则、计分和变量含义。

目标不是支持所有平台，而是先规定一份最小稳定接口，使平台特有代码集中在适配器中。

**后端协议**指接口方法、字段、认证、响应和错误处理；**研究方案**指题目、条件与反馈安排。二者独立编号，不因更换 API 而自动更换研究设计。

## 2. 五层划分

```text
① 实验界面：jsPsych、老虎机卡片、问卷、信心与反馈
                    ↓
② 实验控制：阶段顺序、响应锁定、事件生成、保存状态
                    ↓
③ 稳定接口：会话、材料访问、结果保存、完成确认
                    ↓
④ 后端适配器：LocalDemo / JATOS / HTTP API
                    ↓
⑤ 实际服务与存储：JATOS、云函数、数据库、云表格等
```

| 层 | 负责什么 | 不负责什么 |
|---|---|---|
| 实验界面 | 呈现获准显示的内容，收集响应及本地反应时 | 不持有云文档令牌，不直接访问数据库 |
| 实验控制 | 调用统一接口、检查阶段、生成标准事件、处理保存状态 | 不使用平台账号 ID 替代研究编号，不出现平台专属分支 |
| 稳定接口 | 定义输入、输出、错误及能力声明 | 不规定必须使用 REST、JATOS SDK 或某种数据库 |
| 后端适配器 | 认证、平台字段转换、上传与恢复、响应标准化 | 不修改实验正确答案、条件及变量含义 |
| 服务与存储 | 持久化、权限、会话状态及所需服务端计算 | 不自动获得研究解释或 α 的心理含义 |

JATOS API、fetch 和其他平台 SDK 仅出现在适配器内部。逐题的 jsPsych 插件调用实验控制层，而不是直接调用 `jatos.*`。

## 3. 数据收集与实验服务分开

需要单独区分两个职责：

- **实验服务**：参与码验证、固定分组、按阶段提供题目和建议、揭晓结果、核算积分。
- **结果存储**：接收事件、持久保存、导出和备份。

云表格能接收记录，不代表它自动提供实验服务。正式实验若要求隐藏未来开奖结果、服务器校验积分，必须由相应服务实现。

JATOS 的基础接入主要解决托管、参与入口和结果保存；自定义服务端开奖、断线恢复及幂等提交等必须另行核验或补充，不能仅凭选择了 JATOS 就声明支持。

原型允许 `LocalDemo` 同时模拟这些职责，便于先开发界面；本地模式不对真实参与者开放，也不能显示“数据已上传”。

## 4. 最小接口约定

以下是项目自定义规格，不是任何平台的现成 API。采用 TypeScript 类型实现，具体 HTTP 路径由适配器决定。

| 方法 | 输入 | 输出/承诺 |
|---|---|---|
| `openSession` | 参与码或邀请凭证、研究方案版本 | 不可猜测的会话身份、研究编号、固定分组、后端能力 |
| `loadState` | 当前会话 | 已确认阶段、最后确认事件、可恢复状态 |
| `loadTrial` | 当前试次标识 | 此阶段允许显示的材料，不含未来答案或私有种子 |
| `saveEvents` | 同一会话的标准事件批次 | 逐事件保存回执；允许部分成功，但必须明确列出 |
| `getFeedback` | 当前试次 | 合法提交后才可返回的结果及积分 |
| `finishSession` | 当前会话、预期结束状态 | 完整性校验后的完成状态与完成码 |

内部可拆成 `SessionService`、`TrialService`、`ResultStore` 三个接口，由装配模块组合。结果查看和导出由研究者权限接口承担，不暴露给参与者适配器。

### 通用事件

每条原始事件至少含：

```text
schema_version
study_id / protocol_version / material_version / client_version
session_id / participant_id
event_id / sequence_no
trial_id（适用时） / phase / event_type
client_timestamp / elapsed_ms
payload
```

服务器另外添加接收时间和提交状态。AI 建议、实际开奖结果和服务器计分按权威来源记录，不能用浏览器声称的数值覆盖。数据字典以主规划为准，适配器只转换存储形式。

### 通用保存回执

```text
acknowledged_event_ids
rejected_events（事件编号与原因）
persisted_at
session_status
receipt_id（若后端支持）
```

收到 HTTP 200、请求已发送或写入浏览器缓存都不等于远程持久保存。适配器只能将后端明确确认保存的事件标记为 acknowledged；若平台响应不足以证明，必须报告状态不确定。

### 通用错误

`INVALID_ENTRY_CODE`、`SESSION_EXPIRED`、`INVALID_EVENT`、`EVENT_CONFLICT`、`OUT_OF_ORDER`、`RATE_LIMITED`、`NETWORK_UNAVAILABLE`、`PERSISTENCE_UNCONFIRMED`、`UNSUPPORTED_CAPABILITY`。

每项错误提供是否可重试、是否需要重新进入，以及可展示的中文信息。原始平台错误留在技术日志，避免暴露密钥和个人信息。

## 5. 能力声明与真实限制

每个适配器声明经验证的能力，例如：

```text
persistentResults
idempotentWrites
resumeSession
serverControlledTrials
serverScoring
individualEntryCodes
```

“尚未验证”与“已支持”分别表示，不能一律填写 true。实验配置列出必需能力，启动时核对；缺少必需能力则不进入正式收集，不能静默降级为客户端评分或无恢复模式。

如果平台没有幂等写入，简单重试可能重复记录。适配器须使用平台支持的机制、补充服务或恢复协议解决；若做不到，就标明限制。表格里增加 event_id 并不自动实现并发去重。

## 6. 保存、中断与恢复

1. 响应生成事件时即确定 event_id，重试不得更换编号。
2. 写入本地待发队列，顺序上传，等待逐事件确认后移出队列。
3. 关键响应在服务器确认前不进入不可逆的揭晓或结算阶段。
4. 中断后以服务器已确认状态为准；刷新不能重新分组或重新生成开奖序列。
5. 客户端提供的状态不能覆盖服务器记录；相同 event_id 的不同内容必须报冲突。
6. 实验结束需等待所有必需事件保存并完成完整性检查；不确定时显示“尚未确认提交”。

本地缓存只提升断网恢复机会，不承诺清除浏览器后恢复。选择单次链接的平台还须检查误点击、刷新与重新进入策略是否兼容上述流程。

## 7. 后端替换与版本边界

- 在配置入口选择适配器，实验插件和题目逻辑不因此改写。
- 默认按实验批次切换。正在进行的会话固定原后端，不在半途迁移。
- 每条记录保存 protocol_version、schema_version、adapter_version 及后台 provider 标识。
- 保留标准 JSON 事件作为交换格式；CSV 是按固定数据字典生成的分析视图，不能靠不同平台自行猜列名。
- 历史迁移另作显式任务：备份、导出、导入、数量校验、逐题字段核对和重新评分；换适配器不会自动迁移旧数据。
- 身份与支付映射单独处理，不随着分析数据导出自动传播。

```text
src/
```

云表格通常作为 HTTP 后端的服务端存储适配器，不建立把管理令牌放入浏览器的 `wps-client` 或 `tencent-docs-client`。

## 9. 实施顺序及验收

1. 先实现数据字典与接口，再用 LocalDemo 跑通 jsPsych 流程。
2. 根据实际部署条件选择第一个真实后端；JATOS 为优先评估对象，不预先购买或部署。
3. 将同一套固定演示材料通过本地适配器和真实适配器运行，对照导出，验证字段、阶段与计分一致。
4. 测试重复提交、断网重试、部分成功、刷新、会话结束和跨会话访问；不得仅以“收到一条记录”判定后台完成。
5. 对照正式实验必需能力，记录后端仍缺少的服务端逻辑，再决定补充还是更换。

无需一开始实现三个生产后端。首版只做 LocalDemo 加一个真实后端，保留替换接口即可。

验收目标：更换适配器及配置时，实验时间线、题目规则与分析字段不变；平台特有调用不会散落到 jsPsych 插件中。若替换改变了参与流程或信息呈现，应记录为研究方案变更，不能称为纯技术替换。

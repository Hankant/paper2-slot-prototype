## B / C / D 可继续工作的条件（contract 0.2.0）

> B/C/D 的具体启动条件与禁止项与 0.1.0 handoff 一致；差别仅在以下三点新增：

**新增三条（合同升 0.2.0）**

1. **Event envelope 的 `payload` 是 round-trip 字段**。B/C 在保存事件时必须保留客户端的 payload；ResultStore 不允许「保留事件但删除 payload」。
2. **PublicTrial 必带 advice block**（advice_timing ≠ 'none' 时）。B 的 UI 与 C 的 LocalDemo 都应以 advice_timing 配置决定是否渲染。
3. **SaveReceipt 的远端确认必须带 `persisted_at` 与 `receipt_id`**。C 在 G1 实现 LocalDemo 时若切到 `memory`/`browser_local`，不应伪造持久时间戳；实现真实后端时务必携带。

**接口版本细节**

- `contract_version = schema_version = material_version = client_version = 0.2.0`；`protocol_version = unreleased`；`demo config = demo-0.2.0`。
- 任何接口字段变更（含新增）需提交变更请求：A 升版本号 → 升 lockfile → 通知 B/C/D。

**进口路径（兼容 0.1.0 与 0.2.0）**

- 等价：`from '../../../src/contracts/index.js'`（相对路径，按文件位置）。
